Manual MySQL root password change notes for XAMPP / MariaDB.

IMPORTANT:
- Do not run these commands until the config files have been deployed.
- Back up the database first.
- Keep the password out of public commits/logs when possible.
- These commands are notes only; they were not executed by Codex.

1) Backup / precautions

- Export the andromeda database from phpMyAdmin or with mysqldump.
- Keep a copy of the current site and emulator config files.
- Stop public access or enter maintenance mode before changing credentials.
- Confirm which root accounts exist before running ALTER USER.

2) Open a terminal in:

C:\xampp\mysql\bin

3) Connect before the change, while root still has no password:

mysql -u root

4) Check the root accounts:

SELECT User, Host, plugin FROM mysql.user WHERE User = 'root';

5) Change the local root password:

ALTER USER 'root'@'localhost' IDENTIFIED BY 'lefaucheuristheking123';

6) If a root@127.0.0.1 account exists, change it too:

ALTER USER 'root'@'127.0.0.1' IDENTIFIED BY 'lefaucheuristheking123';

7) If ALTER USER is not supported by the installed MariaDB/MySQL version,
use the compatible fallback instead:

SET PASSWORD FOR 'root'@'localhost' = PASSWORD('lefaucheuristheking123');
SET PASSWORD FOR 'root'@'127.0.0.1' = PASSWORD('lefaucheuristheking123');

8) Reload privileges:

FLUSH PRIVILEGES;

9) Verification after the change:

mysql -u root -p

Then enter the new password when prompted.

SELECT DATABASE();
SHOW DATABASES;

10) phpMyAdmin follow-up

Check:

C:\xampp\phpMyAdmin\config.inc.php

- If auth_type is config and root/password are hardcoded, set the new root password there.
- If auth_type is cookie, log in manually with root and the new password.

11) Rollback note

If the site/emulator cannot connect after the change:

- Re-check every config file that still uses root with an empty password.
- Re-check whether the app connects through localhost or 127.0.0.1 and whether both root accounts were updated.
- As a last resort during maintenance only, reconnect to MySQL with the working root account and set a temporary known password again, then update files to match.
